## 🔍 Технические детали

### Предотвращение кеширования

Telegram Mini Apps агрессивно кешируют контент. Для решения этой проблемы были внедрены три уровня защиты:

1. **Динамическая версия URL** - каждый раз при открытии бота генерируется новый URL с меткой времени
2. **HTTP заголовки no-cache** - браузер не сохраняет страницы в кеш
3. **Service Worker отключен** - предотвращает оффлайн-кеширование

### Логика аутентификации

```
1. Пользователь открывает приложение
   ↓
2. Отображается LoadingScreen (1.5 сек)
   ↓
3. Проверка: есть ли токен в localStorage?
   Да → Проверка валидности → Переход на главную
   Нет → Перенаправление на EntryPage
   ↓
4. EntryPage: аутентификация через Telegram WebApp
   ↓
5. Получение профиля: заполнен ли профиль?
   Да → Переход на главную
   Нет → Переход на регистрацию
```

### Генерация имен пользователей

Теперь используется формат: `Student_{user_id}`

Где `user_id` - это автоинкрементный ID из базы данных, гарантирующий уникальность.

Пример: `Student_1`, `Student_2`, `Student_3`

## ⚠️ Известные ограничения

1. **Кеш Telegram** - В редких случаях Telegram может все еще использовать старый кеш. Решение: полная переустановка приложения Telegram (крайний случай)

2. **Dev-режим** - В разработке генерируются случайные `tgId`, что может создать много тестовых пользователей в БД

3. **Миграции** - После очистки БД убедитесь, что все миграции применены
